Models Tried
FaceFusion 3.5.2 Working
Face Swap Framework · Identity-Transfer GAN (inswapper_128) — ArcFace encoder + single-shot adversarial generator
The only model that reached full, reliable GPU inference on the target task. De facto baseline by elimination, not by design choice.

Architecture: FaceFusion is an inference framework, not a model. Its default backbone is InsightFace's inswapper_128 — an identity-transfer GAN (~130M params) in the FaceShifter family. ArcFace encodes the source identity into a 512-d embedding; a single-shot adversarial generator then transfers that identity onto the target face in one forward pass via AdaIN feature injection, with no per-identity fine-tuning required. Processes 128×128 aligned face crops; a post-processing enhancer (GFPGAN, CodeFormer) is required to recover fine detail lost at that resolution.

Status: Fully operational with GPU acceleration.

Output: Qualitatively satisfactory identity transfer on video. Strong identity fidelity is a product of ArcFace's training quality, not architectural novelty.

  • Required Python 3.11 (networkx 3.6.1 constraint)
  • cuDNN 9 had to be manually installed from NVIDIA sources
  • 128px native resolution — fine detail requires post-processing enhancer
  • Stops at hairline — deliberate mask boundary, causes hair inconsistency
  • No temporal modeling — frame-by-frame, flickering in fast motion
  • Face-only — ignores body, clothing, full-body replacement not possible
  • Won by default: all architecturally stronger alternatives failed at setup
Roop Partial
Face Swap Framework · Identity-Transfer GAN (inswapper_128, identical to FaceFusion)
Ran inference but uses the same underlying inswapper_128 model as FaceFusion — no architectural differentiation.

Architecture: Identical backbone to FaceFusion (inswapper_128 via InsightFace). Roop is a thin wrapper around the same ONNX model. No unique model capability over FaceFusion.

Status: Functional but redundant given FaceFusion is available.

Output: Face swaps produced; quality indistinguishable from FaceFusion with same backbone.

  • Dependency conflicts required manual resolution
  • Same architectural limitations as FaceFusion: 128px, no temporal modeling, hairline boundary
  • Effectively a duplicate baseline — no value added for comparison
AlphaFace Partial
Reference-based Image Swapper · ArcFace-conditioned encoder-decoder (no temporal component)
Generated 200 swapped images (4 sources × 50 targets). First confirmed output, but purely image-scoped — revealed the need to reframe the research toward true video models.

Architecture: Reference-based image swapper. ArcFace-conditioned encoder-decoder that takes a single reference face and a target image; no recurrence, no temporal state, no video-level reasoning. Same architectural family as inswapper — the distinction is it was evaluated as a standalone research model rather than wrapped in a production pipeline.

Status: Ran end-to-end on images only.

Output: 200 face-swapped images. No video generation capability.

  • No temporal modeling whatsoever — applying frame-by-frame causes severe flickering
  • Image scope only — fundamental mismatch with video research goal
  • Line ending issues and missing pytorch-msssim at setup
MimicMotion Partial
Full-Body Generation · Full-Latent Synthesis (SVD U-Net, pose-conditioned)
Ran successfully with smooth motion transfer. Background replacement is not a bug — it is a direct consequence of the full-latent synthesis architecture.

Architecture: Built on Stable Video Diffusion (SVD). Uses DWPose skeleton sequences to condition a diffusion U-Net on motion. Critically, this is a full-latent synthesis model: it denoises the entire frame latent from noise, meaning every pixel — foreground and background — is generated fresh. It is not an inpainting model and has no mechanism for preserving original background pixels. Background replacement is therefore an architectural property, not a tuning failure.

Status: Ran and produced output. Not suitable for the replacement task.

Output: Smooth motion transfer but fully synthesised backgrounds; identity preservation degrades on non-frontal views.

  • Full-latent synthesis — entire frame regenerated from noise, source background discarded by design
  • Identity fidelity degrades significantly on non-frontal views
  • Correct tool for animation tasks; wrong tool for scene-preserving replacement
VideoPainter Partial
Video Inpainting · Dual-stream CogVideoX (DiT) + SAM2 tracking
3-stage pipeline (SAM2 → DWPose → CogVideoX inpainting). Most architecturally appropriate for the task, but heaviest engineering effort.

Architecture: Dual-stream Diffusion Transformer (DiT) built on CogVideoX. One stream processes the preserved background (unmasked region), the other generates inpainted content conditioned on text and an identity reference. SAM2 propagates the person mask across frames. Theoretically the most task-appropriate architecture in this study.

Status: Pipeline runs but output quality not production-ready.

Output: Initially gray screen (VAE normalization bug). After fixes: ghosting and blending artifacts persist.

Root cause of ghosting: Two compounding factors. First, the VAE bottleneck — the encoder compresses frames into a continuous latent space that inherently blurs the hard boundary between masked and unmasked regions; the decoder reconstructs a smooth blend, not a hard cut. Second, soft masking from SAM2 — SAM2's mask edges are feathered rather than binary, so the model sees a gradient transition zone around the person boundary and treats it as a region to blend across, ghosting the original face into the generated replacement.

  • VAE normalization bug — [-1,1] range clipped to [0,1], destroying half the dynamic range (fixed)
  • BFloat16 / Float32 dtype mismatch between DiT transformer and VAE (fixed)
  • VRAM peaked 50-55GB on 48GB L40S — CPU offloading + VAE tiling required
  • After optimizations: stable at 38-42GB with ~15-20% speed overhead
  • VAE bottleneck + soft SAM2 masks produce structural ghosting — not fixable without hard binary masking and post-composite blending
HunyuanVideo-1.5 Partial
Image-to-Video · Diffusion Transformer (DiT) — full attention over space + time (Tencent, Dec 2025)
State-of-the-art upper-bound baseline. ~70GB model stack fully downloaded and configured. Inference pending.

Architecture: Full Diffusion Transformer (DiT) — replaces the U-Net backbone used in older diffusion models (SVD, SD 1.5) with a pure transformer that attends jointly over spatial and temporal dimensions. This is why the model stack reaches ~70GB and VRAM requirements far exceed U-Net-based models: the transformer scales quadratically with sequence length (frames × spatial tokens), and each component (transformer, VAE, LLaMA text encoder, CLIP encoder, vision encoder) is large independently. Included as an upper-bound quality reference, not a face-swap baseline.

Status: All components downloaded, dependencies resolved. Inference not confirmed at report time.

Output: N/A — pending.

  • DiT quadratic attention scaling drives VRAM far above U-Net equivalents
  • Multi-component path configuration required careful alignment
  • Not a face-swap model — full-latent I2V synthesis, no identity injection
InsightFace InSwapper Abandoned
Face Swap · FaceShifter-style encoder-decoder + ArcFace (same backbone as FaceFusion)
Direct Python API access to inswapper_128 without the FaceFusion wrapper. GPU never operational.

Architecture: Identical to FaceFusion's backbone. Attempted direct use via InsightFace Python library for programmatic access to intermediate features and embeddings — useful for evaluation pipelines.

Status: CPU fallback only — not viable for benchmarking speed or throughput.

  • Missing cuDNN library blocked GPU execution entirely
  • GitHub model downloads failed — partially resolved via Hugging Face mirror
  • Abandoned in favour of FaceFusion which wraps the same model with full GPU support
FSGAN Abandoned
Face Swap + Reenactment · RNN-based temporal consistency (ICCV 2019) — legacy architecture
Only initial candidate with native temporal consistency via RNN recurrence. Pioneer in video-native face swapping, but pre-dates spatio-temporal transformers.

Architecture: Recurrent generator (RNN-based) with subject-agnostic training. Includes explicit face reenactment (expression transfer) followed by a completion/inpainting stage and occlusion-aware segmentation. Temporal consistency is achieved via recurrent hidden state propagation across frames — a fundamentally different and more limited approach than the joint spatio-temporal attention used in modern DiT models like HunyuanVideo. FSGAN was a pioneer for video-native swapping in 2019; by 2026 standards it is a legacy architecture.

Why it matters: Most architecturally relevant abandoned model. Its failure was entirely infrastructure — it would have been the only model providing a meaningful video-consistency comparison against FaceFusion.

  • face_detection_dsfd C++ module failed to compile — CUDA 11.6 kernel support absent on L40S / modern server GPUs (sm_89+ architecture)
  • Hardcoded PyTorch 1.12.1 + CUDA 11.6 dependency stack — these CUDA versions predate the compute capability of 2024-era server GPUs
  • Import errors at runtime unresolvable without forking and patching the detection module
SimSwap Abandoned
Face Swap · UNet generator + Identity Injection Module (ACM MM 2020)
Strong academic baseline with published benchmarks on FaceForensics++. Never reached inference.

Architecture: UNet-style generator with a dedicated Identity Injection Module (IIM) that transfers ArcFace embeddings into intermediate feature maps via AdaIN. Designed to decouple identity from attributes (expression, pose, lighting) more explicitly than FaceShifter. Not a GAN in the pure sense — no adversarial loss at inference.

Why it matters: Would have provided a legitimate academic comparison point with published benchmark numbers. Loss was purely model distribution failure.

  • Broken Google Drive links for all pretrained checkpoints
  • Missing requirements.txt in repository
  • gdown failed due to Drive permission restrictions — no public mirror available
DeepFaceLive Abandoned
Real-Time Face Swap · SAE encoder-decoder (DeepFaceLab lineage)
Real-time capable face swap with live webcam/video stream support.

Architecture: Uses DeepFaceLab's SAE (Structured Autoencoder) variant, optimised for real-time streaming. Shared encoder, separate decoders per identity. Different paradigm from inswapper — requires some per-identity adaptation, not fully one-shot.

  • Python version incompatibilities at environment setup
  • Missing CUDA libraries not resolvable without major environment restructuring
REFace Abandoned
Face Reenactment · Expression + pose transfer (not face swap)
Attempted as an identity-preserving reenactment alternative to MimicMotion.

Architecture: Reenactment model — transfers expression and pose from a driving video to a source identity without swapping identities. Different task from face swap: source identity is preserved, not replaced. Relevant for animation use cases rather than deepfake replacement.

  • Persistent dlib compilation failures — C++ build dependencies missing on server
  • No conda-free installation path available

Findings

Open-source model maintenance is a real research obstacle

Several academically strong models (SimSwap, FSGAN) were effectively inaccessible due to broken distribution links, missing files, and abandoned repositories — not conceptual flaws. This skewed the selection toward tooling-oriented projects over research-grade implementations with published benchmarks.

CUDA compute capability killed the most relevant models

FSGAN, DeepFaceLive, and REFace all failed at the C++ compilation stage because they were built for CUDA 11.x, which lacks kernel support for sm_89+ GPU architectures (L40S, RTX A6000 Ada). This is a systemic problem: older models that required native CUDA extensions simply cannot run on 2024-era server hardware without significant porting effort.

No single model covers the full replacement task — for distinct architectural reasons

Face-swap models (FaceFusion/inswapper) preserve backgrounds but operate frame-by-frame with no temporal state. Full-latent synthesis models (MimicMotion, HunyuanVideo) regenerate every pixel from noise — background preservation is architecturally impossible, not a configuration issue. Inpainting models (VideoPainter/CogVideoX DiT) preserve backgrounds but the VAE bottleneck and feathered SAM2 masks structurally ghost the original content into the generated region. Each failure mode is fundamental, not tunable.

FaceFusion as de facto baseline — not by merit

FaceFusion (identity-transfer GAN: ArcFace encoder + single-shot adversarial generator via inswapper_128) became the working baseline by elimination. The architecturally stronger candidates — FSGAN (RNN-based temporal consistency, the only true video model) and SimSwap (UNet + explicit Identity Injection Module with published benchmarks) — both failed before inference due to infrastructure. FSGAN's RNN approach is itself legacy compared to modern spatio-temporal DiTs, but it would still have provided a meaningful video-consistency data point that is currently absent.

Evaluation framework is defined, execution pending

Metrics are fully specified: ArcFace cosine similarity (identity), landmark NME (pose/expression), temporal LPIPS (consistency), FID on face crops (realism), and 95th-percentile latency/FPS (performance). Quantitative benchmarking against working models is the immediate next step.
